## 3. 参数值实际写法

### 阻值（`name='阻值'`，Top 20）

`10kΩ`、`1kΩ`、`100Ω`、`10Ω`、`100kΩ`、`2kΩ`、`150Ω`、`1.5kΩ`、`470Ω`、`20kΩ`、`4.7kΩ`、`200Ω`、`15kΩ`、`2.2kΩ`、`220Ω`、`15Ω`、`75Ω`、`330Ω`、`47Ω`、`1Ω`。

- 单位统一带 `Ω`，没有观察到裸 `10k`；千位用 `k`，兆位用 `M`，小数保留（如 `1.5kΩ`、`4.7kΩ`、`7.5kΩ`）。
- 用户输入 `10k` / `10K` / `10000` 时，需要归一化后命中 `10kΩ`。

### 精度（`name='精度'`，Top 10）

`±1%`（98,180）、`±5%`（87,895）、`±10%`（72,847）、`±20%`（56,926）、`±0.5%`（48,656）、`±0.1%`（33,856）、`±2%`（30,019）、`±0.25%`（19,278）、`±0.05%`（4,952）、`-`（1,801）。

- 主流写法带 `±` 和 `%`；用户输入 `1%` 时，需要去掉 `±` 后命中。
- 还存在范围值（`-20%~+80%`、`-10%~+75%`）和非百分比容差（`±2℃`、`±0.5℃`），归一化不能把它们强行套成单一百分比。
- `1%` 单独匹配约 98,180 行，选择性很低；搜索应依赖其他 token 或“本地有货优先 + 限量”，不能把 `1%` 当作高选择性条件。

### 容值（`name='容值'`，Top 10）

`1nF`（5,969）、`1.5nF`（5,059）、`2.2nF`（4,949）、`470pF`（4,870）、`220pF`（4,766）、`4.7nF`（4,724）、`330pF`（4,712）、`100pF`（4,658）、`10nF`（4,606）、`150pF`（4,478）。

- Top 40 全部是 `pF` / `nF`，没有出现 `uF` / `µF`；`100nF = 0.1uF` 属于查询别名，不是库内写法，必须用合成用例覆盖。
- `pF` / `nF` / `uF` 之间的换算需要按数值归一，不能只做字符串替换。

### 额定电压（`name='额定电压'`，Top 10）

`50V`（44,399）、`25V`（36,496）、`100V`（35,909）、`16V`（26,491）、`250V`（22,560）、`200V`（22,393）、`10V`（18,294）、`63V`（15,488）、`500V`（13,820）、`1kV`（8,462）。

- 存在 `kV` 写法（`1kV`、`1.5kV`、`1.2kV`、`2kV`），归一化应覆盖 `1kV = 1000V`。
- `-` 是空值占位，不应被当作可搜索值。

### `detail_value`

抽样中 `detail_value` 与 `value` 相同（如 `30kΩ`、`±1%`、`1nF`），且 4,110,477 行全部非空。参数搜索以 `value` 为主即可，`detail_value` 暂不作为独立检索源。

## 4. 索引与检索字段

- `pg_trgm` 已安装。
- `lab_catalog_item` 已有两个 trigram GIN 索引：
  - `lab_catalog_item_trgm_idx`：`search_text gin_trgm_ops`
  - `lab_catalog_item_name_trgm_idx`：`name gin_trgm_ops`
- `lab_catalog_param` 只有 B-tree 索引：`code`、`item_id`、`name`、`value`、`(code,value)`、`(item_id,code,value)`、`(name,value)`；没有 trigram GIN。
- `search_text` 当前长度 30–203，512 上限未触顶；因此“参数塞不进 512”不是当前事实。分离 `search_params` 的主要理由应改为：独立策展、独立回填、避免身份字段与参数耦合、避免导入器重建逻辑互相影响。

## 6. 对设计的影响

1. 归一化规则按真实写法调整：`Ω` 后缀、`k/M` 前缀、小数、`±%`、`kV/V`；`uF/µF` 作为查询别名补充。库内低阻值统一写 `Ω`（如 `10Ω`），但用户常用 R 记法（`10R`=10Ω、`4R7`=4.7Ω、`R1`=0.1Ω）；归一化必须生成这些查询别名，常见 `4k7`/`1k5` 也要覆盖。
2. 关键参数仍按中文名选取；`温度系数`、`工作温度`、`工作电压` 是高频参数，但不在现有电阻/电容标签集合内，参数搜索不会覆盖它们。这是与标签逻辑一致的已知边界，不应在实现时悄悄扩大。
3. `parameterCode` 在生产数据中稳定映射到名称；实现仍以名称为准，但回填/迁移可用 code 对齐。
4. `search_text` 长度有充足余量；不扩展它，是为了独立策展和新鲜度，而不是长度溢出。
5. 新增 `search_params` 的 trigram GIN 索引和 695,217 件 / 4,110,477 行参数的回填是生产级操作；索引构建、分批回填、监控和回滚必须单独授权，不能混在普通代码合并里。
6. `1%`、`1k` 等短 token 的选择性低；`pg_trgm` 对 2 字符 token 的收益有限，查询计划需要用真实数据 `EXPLAIN` 验证。
7. 本地档案只有 2 条空记录；`lab_search_specs` 字段和测试可以落地，但不能宣称真实本地件覆盖通过。
8. 供应商库存不参与“有货”；本次审计没有读取或改动库存表，排序规则不变。
