## 结论

“选择器件无反应”不是建议面板没弹出来，而是**选中后的三条静默路径**：

1. `_selectSuggestion` 原来经 `_run()` 执行，`_busy` 为真时直接 return，点击被吞掉。
2. 档案 `detail()` 未返回前界面不改任何状态；返回慢就像没点；抛错时旧代码把选中整条丢弃。
3. 面板被外部点击关闭后输入框仍有文字，再点输入框不重新搜索（`TextField` 没有 `onTap`）。

修复（`clients/app`）：

- `pending_receipt_screen.dart`：选中**当帧提交**（`_item` 立即赋值），随后异步读档案；读取中显示“已选中，正在读取内部档案…”并禁止建袋；失败仍保留选中并提示“已选择…但读取内部档案失败…”。新增 `_selectionFromSuggestion`，按“是否来自建议”而不是比对 `item_key` 清除选中（详情会把 `lcsc:C…` 换成 `lab:…`）。
- `catalog_suggest_search.dart`：`onTapAlwaysCalled` + `_onFieldTap`，关闭的面板在再次点击输入框时重新搜索；`_pickedLabel` 防止把选中回写的标签当查询再次发送。

## 构建环境坑（下次直接照做）

1. `build_client.py` 的 `--pub-cache` 原样交给子进程，子进程 cwd 是构建副本；**相对路径会被解析到副本里**，`pub get --offline` 报“could not find package json_serializable in cache”。必须传绝对路径。
2. Windows 的 `printing 5.15.1` 需要带 `PDFIUM_LOCAL_ARCHIVE` 支持的副本（本工作区 `local/pub-cache-windows` 有）；`dependencies/pub-cache-windows` 是原版，会去 GitHub 下 pdfium，本机拿到 0 字节后 CMake 失败。环境变量指向 `dependencies/windows/pdfium-win-x64-5200.tgz`。
3. 构建命令必须显式传 `--flutter`（本工作区 `dependencies/` 只有离线载荷，没有 SDK）。
