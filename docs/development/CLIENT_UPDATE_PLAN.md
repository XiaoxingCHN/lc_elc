# 客户端启动检查与自动下载更新方案

日期：2026-10-19。状态：方案，尚未实现或发布更新器。适用 Windows、Android、Linux 共享 Flutter 客户端。

## 目标与默认行为

每次打开应用，在后台检查当前配置服务器的客户端发布清单；服务器可达且存在适配新版本时，自动下载、验证，提示用户安装。检查不阻塞首屏和登录；离线仍遵守公开缓存只读。默认在非计费网络自动下载，计费网络先显示大小并由用户确认；网络类型无法确认时按计费处理。安装必须等当前业务操作完成并由用户确认，不能中断入库、领料、打印或未决重试。

流程：启动 → 请求版本清单 → 校验清单/比较本机版本 → 下载临时文件 → 验证完整性和发布身份 → 显示“更新已就绪” → 确认安装 → 平台安装流程 → 重启核验。

启动离线时保持待检查，在应用前台恢复、网络变化或现有服务器请求首次恢复成功时重试；这些事件仅触发探测，不能把“连上Wi-Fi”当成服务器可达。每次启动只保留一个检查任务，同一版本只提示一次，失败退避30秒、2分钟、5分钟、15分钟；切换服务器取消旧任务并丢弃迟到响应。设置页保留“检查更新”和下载进度/重试入口。检查成功不改变十天登录有效期，也不触发隐式重新登录。

## 服务器与发布来源

GitHub保存源码和提交记录；服务器只分发经过正式验收、由管理员发布的不可变安装包及清单。现有1.1.0+3仍是本地候选，不能直接标记为stable最新版；本轮上传源码也不等于发布安装包。暂不让每台客户端访问私有GitHub资产，服务器发布流程也不把token写入客户端。

建议新增两个只读入口（路径暂定，实施时同步API契约）：

- `GET /lab/client/updates/manifest?platform=...&arch=...&channel=stable`：最小匿名发布元数据，不要求登录或库存权限，避免登录失效时连版本也无法获知。它本身作为轻量服务器连通探测。
- `GET /lab/client/updates/assets/<release-id>/<filename>`：由现有合法登录会话授权下载；只允许已登记的完整包，不接受任意磁盘路径。下载未登录时显示“登录后下载”，登录成功自动继续。会话凭据仅发往当前服务器同源，禁止跨域重定向携带cookie。

匿名接口只公开本应用的发行元数据，不公开GitHub仓库、账号、库存或部署细节。更新接口与普通业务写接口分开，旧客户端登录/下载不因业务API最低版本门槛被提前阻断。下载可采用同源静态服务加授权校验或有大小/时限限制的流式响应，实施前按现有部署选型，不因方案自动更改代理或网络服务。

清单至少含：schema、app_id、channel、platform、arch、version、build_number、release_sequence、release_id、发布时间、更新说明、包类型、相对下载地址、字节数、SHA256、最低系统版本、支持的服务端API范围、签名key_id和清单签名。build_number按客户端平台实际安装值比较，不能按字符串比较版本；安装包身份、架构或API不兼容时不提示安装。

发布顺序：冻结源码/记录commit → 构建与平台验收 → 安装包校验、签名及证书登记 → 上传完整不可变包 → 核对服务器实物hash → 最后原子切换签名清单。发布指针可撤回，旧包不覆盖；撤回不能使已装新版自动降级。第一版不启用强制升级。

## 下载与三端安装

| 平台 | 安装策略 | 约束与失败处理 |
|---|---|---|
| Android | 完整APK；下载验证后调用系统PackageInstaller，按系统要求确认安装/授权来源 | applicationId及既有签名证书必须一致，实际versionCode递增；不更换密钥、不先卸载旧应用；失败保留现有版本与数据 |
| Windows | 完整bundle压缩包；外部更新助手等待主进程退出，再切换已解压验证的新版本目录并重启 | 不覆盖正在运行的exe/DLL；引入稳定启动器及版本目录，用户可写安装优先；权限不足交给显式安装流程，不自行提权 |
| Linux | 完整tar.gz bundle；助手在用户可写安装目录解压新版本，切换稳定启动入口，保留前一版本 | 保持执行权限和运行库，系统目录需要管理员安装时给出明确入口；不由普通应用执行sudo或修改系统包 |

桌面助手只操作经验证的应用安装根，拒绝压缩包越界、任意绝对路径及逃逸链接；完整解压和检查后才切换。保存升级事务状态；新进程需达到本地启动就绪再标记成功，不能用“服务器可达”判断本地安装成功。失败恢复先前启动入口，保留旧包；首版不做不可逆本地数据迁移。Android回退通过发布修复版处理，不承诺绕过系统降级规则。

下载写入临时文件、限制大小、可取消且不影响业务；断点续传须匹配同一release-id/ETag，否则重下。下载完成校验SHA256、字节数、清单签名及包身份，失败包不可执行。独立发布签名私钥不进入客户端或Git，客户端内置可信公钥；清单签名覆盖包hash和所有安装决策字段，发布序号防重放。通过明确的key_id/受信任轮换流程换钥，不从未验证清单自动信任新钥。更新服务优先HTTPS；当前环境仍有HTTP，不能仅信任HTTP响应内的hash来执行代码。

保留现有账号、缓存隔离和系统安全存储；下载缓存按发行身份/平台/架构/版本隔离，不能落业务凭据。恢复下载时重新获取授权并复验清单，不能持久化会话URL或token。确认安装前检测活跃表单、打印和未决写请求，未完成则延后；更新不得改变服务端库存。

## 实施接入与分期

现有 `main.dart` 提供单一OdooClient，`auth_provider.dart` 维护会话，`unified_providers.dart` 管理作用域，暂无应用更新器。复用现有网络与会话边界，新增共享UpdateService/状态provider和“关于与更新”界面；公开清单请求不触发登录失效，下载沿用同源认证。用平台适配器隔离Android安装和桌面助手。本机版本读取应来自实际安装包/构建元数据，不能依赖界面写死版本；新依赖在实施前核对官方维护状态、离线载荷与三端支持。

1. 先做签名清单、启动/重连检查、版本比较、更新提示、服务端只读发布入口和测试。
2. 加完整包自动下载、进度/取消/重试、身份及完整性校验；完成三端平台安装、桌面切换/失败恢复。
3. 发布首个含更新器的完整安装包，旧1.0.1+2和当前未含更新器的候选需人工安装一次；此后进行“旧版启动→发现新版→下载→确认安装→保留数据”的真实升级验收，再开放stable。

下一版客户端独立递增版本/build号；若新增Odoo控制器则独立递增lab_workflow版本，不能为了发客户端包复用已上线服务端版本。客户端更新只更新客户端；服务端上线仍走独立授权和备份流程。

验收覆盖：在线启动、启动离线后重连、登录失效、相同/更低版本、平台/架构/API不匹配、重复事件/切服迟到响应、计费网络、下载中断/磁盘不足/并发启动、hash或签名错误、跨域凭据泄漏、解压越界、安装拒绝/权限不足、桌面进程锁定/重启失败恢复、Android证书不匹配、升级后账号/缓存/十天规则保留，以及库存前后不变。没有原生升级实测的包只能标candidate。

## 平台依据（2026-10-19查阅）

- [Android PackageInstaller用户操作要求](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int))：普通安装路径应处理系统要求用户确认的状态，不能承诺静默安装。
- [Windows App Installer更新设置](https://learn.microsoft.com/en-us/windows/msix/app-installer/update-settings)：MSIX支持启动检查；当前是便携bundle，首版沿用完整bundle更新助手，若后续采用MSIX需单独验证签名/安装身份迁移，不能直接套用其自动更新能力。
- [GitHub Release资产API](https://docs.github.com/en/rest/releases/assets)：提供发行资产和下载接口；本方案经服务器分发，不把私有仓库认证下发给客户端。
