# 需求基线与业务边界

## 已确认流程

1. Windows/安卓/Linux业务一致。记住账号和安全登录状态，距上次成功登录超过10天需重新输入密码。
2. 主仓库统一展示实验室库存与立创资料；绑定记录合并，同器件汇总多库位/批次，有库存前置；分类导航、多条件筛选、图片列表和参数详情。
3. 扫码入库、领用、归还。领用人必须选择系统账号；归还关联原领用行。例：A领10个后归还3个，该原领料记录剩余可归还7个，不能归还到另一条不相干记录。
4. SN和库位绑定，袋追溯记录入库/领用/归还。器件标签只显示一个追溯二维码，库位标签单独是库码；文字显示参数等信息。用户设毫米尺寸后批量排入A4。
5. 图片和手册日常联网加载，缓存已查看/已入库器件；离线只读已缓存公开内容，离线不进行库存写入。
6. Odoo浏览器默认进入仓库，移动端可返回；当前1.0.1采用轻玻璃风格UI。
7. Odoo只保留设置、网站和实验室库存入口，相关依赖不卸载；普通权限表只显示网站/实验室，完整技术权限在开发者模式保留。

## 后续单独增加的EDA范围

最早一轮完整交付明确排除BOM/EDA、盘点调拨、Excel等；之后用户另行要求EDA插件并实际形成3.0.3，所以本仓库保留插件及已有BOM相关源码。不要把此前排除的所有功能重新推断为已交付需求。具体EDA当前功能和验收限度见插件MAINTENANCE。

## 不得混淆

- 供应商可售数量不等于本地库存。
- 全量历史需求草稿不等于现行范围；新需求要通过任务单明确。
- 当前包已构建不等于每个平台都重测了实体扫码/打印。Android按用户约定未模拟器验证，Linux1.0.1没有重新完整做SecretService/CUPS验收；记录限制。
- 本次归档不自动增加业务、清理生产数据或重新部署。
