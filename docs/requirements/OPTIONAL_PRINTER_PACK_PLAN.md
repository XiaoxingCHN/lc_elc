# 客户端打印接口与精臣功能包方案

**状态：未来规划，暂缓实施。** 恢复前重新核对客户端版本、打印机实机条件及精臣 SDK 和字体的再分发许可。方案覆盖 Windows、Android、Linux 的 Flutter 客户端。项目内只维护已在用的精臣 B1 Pro 适配，其他厂商通过公开打印接口接入。EDA 不参与打印功能包。

## 目标与现状

公开客户端保留所有现有库存作业、标签预览、PDF 导出和系统打印。精臣热敏直打由用户选装。缺包、断连、权限拒绝或接口不兼容时，界面明确说明，并保留系统打印。客户端的升级与功能包的升级分别管理。

- Windows 主客户端使用 Dart FFI 加载精臣 DLL。CMake 将运行时和字体复制到安装目录，桌面更新器切换整个 bundle，同目录的附加文件可能随旧目录移走。 [Windows 打包](../../clients/app/windows/CMakeLists.txt#L121) · [直打调用](../../clients/app/lib/services/niimbot_printer.dart#L730) · [桌面更新](../../clients/app/lib/updates/desktop_update.dart#L271)
- Android 主 APK 直接编入精臣 SDK 与图像 AAR，通过 `MainActivity` 声明 Flutter 通道和蓝牙权限。`.aar` 是编译依赖，Android 用户侧改用可独立安装的辅助 APK。 [Gradle](../../clients/app/android/app/build.gradle.kts#L69) · [现有桥接](../../clients/app/android/app/src/main/kotlin/com/example/lab_inventory_client/MainActivity.kt#L31)
- 三端已共用标签内容。系统打印由 `Printing.layoutPdf()` 提供，热敏直打也从现有只读标签预览取得 `LabelContent`。 [标签模型](../../clients/app/lib/features/unified/models/labels.dart#L285) · [系统打印](../../clients/app/lib/features/unified/services/pdf_output.dart#L170) · [标签调用](../../clients/app/lib/features/unified/providers/label_providers.dart#L584)

## 接口和分层

| 层 | 责任 |
| --- | --- |
| 客户端标签与打印页 | 使用现有预览接口读内容，统一选标签尺寸、份数、打印机。生成预览，调用系统打印或选装适配器。 |
| 打印适配协议 v1 | 定义能力、发现、连接、提交任务、任务结果和支持的载荷。公开协议、样例和测试，不包含厂商运行时。 |
| 精臣 Windows 功能包 | 独立本机适配器及 x64 驱动、获准随包提供的字体，负责 B1 Pro USB 直打。 |
| 精臣 Android 功能包 | 独立辅助 APK，携带 SDK、获准字体、设备绑定界面和蓝牙权限，负责 B1 Pro 蓝牙直打。 |
| Linux | 默认系统打印和 PDF，保留同一桌面协议给合作方。精臣 Linux 适配待厂商 SDK 可用时再评估。 |

### 打印协议 v1

| 入口 | 约定 |
| --- | --- |
| `getCapabilities` | 返回 `providerId`、`protocolVersion`、支持纸型/分辨率、USB/蓝牙等连接方式、是否报告纸尽或打印完成。客户端握手后才启用入口。 |
| `listPrinters`、`connect` | 返回适配器内部的设备 ID 和名称。按需请求扫码或蓝牙权限，显示可操作的拒绝原因。系统打印继续用系统自己的选择器。 |
| `submit` | 输入 `jobId`、`printerId`、毫米尺寸、方向和已展开页列表。页内包含带位置的文字和唯一二维码。份数由客户端展开一次，适配器逐页打印。协议允许适配器声明支持位图；实际首版精臣按已有图元调用保留版式。 |
| `getJobStatus`、`cancel` | 使用同一 `jobId` 查询。取消仅对适配器尚可撤销的任务生效。区分已接收、已交给设备、设备确认完成、失败、已取消和结果未知。按 `jobId` 记录已接收的请求。同号同内容返回已知状态，同号不同内容拒绝。结果未知先核对，页面禁止自动再打一张。 |

仓库继续从 `LabelContent` 读取追溯码和文字。标签尺寸、固定二维码位置、库码文字与对齐规则可逐步从 `niimbot_layout.dart` 抽为共用热敏版式。袋、待入库袋、库位三类标签沿用现有规则。格式使用毫米，适配器按能力转换点阵和驱动指令。外部适配器只需要标签内容和任务必要参数，登录凭据、Odoo 会话和库存写权限留在客户端及 Odoo。

## 安装、识别与兼容

### Windows x64

- 功能包安装到独立的用户级目录，版本目录包含适配器清单、校验和匹配的私有运行时。升级主程序会换 bundle，功能包目录单独保留。
- 客户端通过明确注册和用户确认识别已安装的适配器。验证功能包来源、签名或发行哈希、平台和协议版本，禁止从当前目录、网络地址或不受信任搜索路径自动加载。
- 适配进程自身按绝对路径加载 DLL，与主应用通过标准输入输出的版本化消息通信，无需本机监听端口。原 FFI、设备扫描和错误映射重用在适配器。第三方适配器作为独立程序运行，用户需要信任其发行者。

### Android ARM64 / ARM32

- 主 APK 移除精臣 AAR、精臣桥接实装和只为直打的权限。通用 Flutter 桥接连接由用户明确选择的辅助 APK。精臣包使用独立 applicationId、签名和版本，用户按 Android 安装流程安装。
- 第一期使用显式绑定的 Android Service 和版本化 IPC，不从网络拉取可执行库。主 APK 核对目标包名、组件及签名证书，服务端核对调用方身份。第三方适配器按同一协议接入，用户明确选择其发行者。蓝牙扫描、连接和设备权限由适配器处理。
- 保持主 APK 原应用 ID 和既有安装签名。主程序保留 Wi‑Fi SSID 等非打印功能仍需的权限。由旧版切换时实测覆盖安装、登录状态和库存流程。功能包独立安装、升级和卸载后主 APK 仍可系统打印。功能包的首次安装按登记包名和证书确认，后续更新再核对版本递增。

### 分发和授权

- 公共 GitHub Release 发布三端通用客户端、打印协议和模拟适配器。通用构建在干净源码上不能依赖本机厂商 AAR、DLL、字体或下载这些文件。
- 精臣功能包是单独的版本和成品，声明客户端最低兼容版本、平台、驱动版本、签名与 SHA-256。未确认公开再分发权之前，公开仓库提供适配源和接入说明，功能包二进制限在获准范围取得或分发。原 Android 接入说明的字体授权限制需一并处理。 [包内材料说明](../../THIRD_PARTY.md)
- 已上线 `1.4.0+26` 的 stable 保留现有行为。过渡期先给现有用户准备并验收独立精臣包，再把生产通道切到通用客户端。通用客户端使用新版本登记。功能包升级等待当前打印任务结束，校验并通过启动探测后才切换，保留上一版回退点。旧版客户端发行目录、已有客户端签名和设备数据保留。

## 实施顺序

1. **抽通用接口。** 保留当前系统打印路径与标签预览契约，定义能力、任务和结果的 Dart 模型，并加入不依赖厂商 SDK 的模拟适配器，用它跑标签三类和倍数校验。
2. **拆 Windows。** 将精臣 FFI 和设备操作挪入单独进程。公开 Windows 构建在缺 SDK 时仍可编译，用户安装功能包后恢复 USB 直打。验证更新主程序和回退后仍能发现功能包。
3. **拆 Android。** 将精臣 AAR、蓝牙界面和打印移至辅助 APK。主 APK 只保留通用连接端，按签名、协议、应用兼容表选择适配器。验证两个 APK 分别更新。
4. **交付接入材料。** 文档化桌面 IPC 和 Android Service，提供纯模拟适配示例及谈判/错误码测试夹具。三端通用包通过验收后发布，授权范围内的精臣包另行发放。

## 验收标准

| 项目 | 通过条件 |
| --- | --- |
| 干净构建与分发 | 三端通用包在无厂商 SDK 的干净构建机成功编译。解包检查无精臣 DLL、AAR 导入、SO、私有字体、密钥及真实配置。所有包独立登记版本、签名和哈希。 |
| 标签兼容 | 使用现行 40×20 mm 袋、待入库袋、库位样本，尺寸、字段、单二维码和份数符合基线。库位码在二维码下、名称可读。字体替换或排版导致超出时在预览报出。打印调用不改变库存。 |
| 通用流程 | 未装功能包时可预览、导出 PDF、系统打印；装上支持的包后出现直打入口。删除功能包或使用不匹配平台/版本时可继续系统打印。 |
| 真机与错误反馈 | B1 Pro Windows USB 和 Android 蓝牙各打印并扫码复核。缺纸、开盖、断连、权限拒绝和 SDK 错误各走对应提示。断开时结果未知的旧任务不自动重复提交。 |
| 更新与安全 | Windows 主程序升级和回退保留功能包；Android 主 APK 覆盖升级保留应用身份和业务数据。签名不符、文件损坏、版本不兼容的功能包在启动或绑定前被拦截。功能包收不到认证信息。 |
| 厂商扩展 | 公开示例不含厂商 SDK。第三方可仅按协议实现 `getCapabilities` 与打印流程，并通过兼容和错误测试，无需修改 Odoo 或复制客户端源码。 |
