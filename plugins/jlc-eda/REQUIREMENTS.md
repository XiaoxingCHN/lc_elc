# EDA 插件需求（2026-11-19 重新梳理）

## 定位

**画图助手**，不是第二个库存系统。

EDA 插件只在“画原理图/PCB 的时候”提供价值：

1. **这个器件有没有库存** —— 以原理图/BOM 里的立创 C 编号为准，查实验室实时可用库存；
2. **有的话在哪** —— 库位路径 + 袋/批次追溯码，让人能直接去货架取；
3. **一键出库** —— 整张 BOM 一次领用，不再逐个器件点。

入库、归还、袋追溯、手动逐个领用**不在 EDA 做**：它们在网页端和 Flutter 客户端已经完整存在，在 EDA 里重复实现等于维护三套状态机，也是本轮架构审查里 H1/H2（误报成功、重复领用）的温床。

## 核心场景（验收标准）

### S1 选中器件查库存

1. 在原理图里选中若干器件 → 菜单「库存联动 → 原理图库存」；
2. 插件自动以「选中器件」为范围，读取这些器件的立创 C 编号；
3. 每个器件显示：位号、C 编号、名称、需求数量、**可用库存**、**库位路径**、**袋追溯码**、状态（有货/缺料/资料库无此件）；
4. 没有 C 编号的器件单独列出，标注“无法查询库存”，不猜测、不合并。

### S2 整工程齐套检查

1. 切到「当前工程 BOM」（制造数据导出，覆盖全部图页）；
2. 按 C 编号归并，显示每行需求、可用、缺口；
3. 顶部汇总：BOM 行数、需求总数、缺口总数、缺料行数、库存未知行数、资料库无器件行数；
4. 支持「仅刷新库存」而不重读 BOM。

### S3 一键出库

1. 齐套检查后点「一键出库」；
2. 插件按袋 FIFO 分配，先预览（dry-run）：显示每个 C 编号分配到的袋、数量、库位；
3. 库存不足时列出缺口，**不扣任何库存**；
4. 确认后提交真实领用单，要求选领用人 + 项目；
5. 结果严格四态（见下），只有真实领用终态才显示“已按袋扣减”。

### S5 同型号不同编号（等效库存）— 3.2.0 已实现

实现位置：`lab_inventory/tools/equivalent_match.py`（判定，纯逻辑）、
`lab.catalog.item.equivalents()` + `/lab/api/catalog/equivalents`（检索，批量）、
`src/shared/bom.js` + `src/iframe/app.js`（候选栏与勾选）。
设计文档：`maintenance/tasks/2026-11-20-eda-persist-login-and-equivalents-design.md` §4。

现实情况：原理图里选的立创器件（如 `C14663` 0.1uF 0402 三星）与实验室实际登记的可能不是同一个 C 编号（如 `C1525` 0.1uF 0402 国巨）。电阻、电容、连接器尤其常见——**型号/规格相同、品牌或立创编号不同**。

规则：

1. **主匹配永远是 C 编号**：精确命中才算“就是它”，出库默认只领这些。
2. **等效候选单独一栏**，不混进主行：
   - 用该 C 编号的**封装 + 关键参数**（容值/阻值/耐压/介质/精度等）检索实验室库存；
   - 命中且 C 编号不同的，标记为「等效：不同编号/品牌」；
   - 每条等效候选必须显示：C 编号、名称、品牌、封装、可用数量、库位、袋码，以及**哪些参数一致**。
3. **绝不自动替换**：一键出库默认只包含 C 编号精确匹配的行；等效候选需要操作员逐行勾选“用等效件替代”才会进入分配，并在领用备注里写明替代关系。
4. **不能判定为等效的不猜**：参数缺失、封装不同、参数冲突（如耐压低于需求）时，只展示为「疑似等效（信息不足）」或不展示，禁止自动归类。
5. 等效检索失败（资料库无参数）时，退化到“同封装 + 同类别”并明确标注依据较弱。

验收：给一条 0.1uF 0402 的 BOM 行，实验室只有另一个 C 编号的同规格电容时，主行显示“缺料”，等效栏显示该电容及库位，勾选后出库才包含它，且领用单备注写明“C14663 → C1525 替代”。

落地时补充的判定细节（设计文档 §4.2 已固化）：

- 硬冲突**直接丢弃**而非「标灰展示」——一个 25V 电容摆在 50V 需求旁边，即使置灰也迟早被误勾。
- 候选**必须有可用库存**（`available_quantity > 0`），没库存的等效件不展示。
- 源器件无封装时不检索，返回 `basis: 'none'`——宁可空着也不猜。
- 整张 BOM 只发**一次**请求，服务端共享一次库存快照（100 行不会触发 100 次 quant 查询）。

参数比对的三个易错点（都有回归测试钉住）：

1. **「耐压」和「工作电压」不是同一条规则。** 耐压是单值上限，越高越好；
   工作电压是**区间**，候选必须完整覆盖需求区间。只看下限会让 `2.0V~2.5V`
   冒充 `1.71V~3.63V`——上界 2.5V 低于需求的 3.63V，实际会烧器件。
2. **带后缀的值仍要参与硬判定。** 立创的真实写法是 `0.1uF ±10%`、`10uF/16V`，
   解析不出完整数值不代表「差异无害」。主值解析失败时按「未比对」处理，
   绝不放行成 `weak`。
3. **`-` 可能是负号也可能是区间分隔。** `1.8V-5.5V` 是区间，`-55~125℃` 的
   前导 `-` 是符号；`±1%`、`-20%~+80%` 这类纯百分比/区间不是可比较的物理量。

### S4 结果四态（复用 shared/outbound.js）

| 状态 | 含义 | UI |
|---|---|---|
| SUCCESS | 服务端返回真实领用单 | 显示领用单明细（issue_line_id / 袋 / 数量 / 未归还） |
| RECONFIRM | 预览后库存或分配变化 | 提示重新预览，**不显示成功** |
| UNKNOWN | 提交后回包丢失 | 保留请求号，提供「原样重试（同键）」「复制请求号」「打开 Odoo 请求记账」 |
| FAILED | 服务端明确拒绝 | 显示错误，**不显示成功** |

## 非功能要求

- **不改服务端接口**；只读路径优先。
- **桥接仍是必需**：EDA iframe 无法直接处理 Odoo 会话 Cookie/CORS，`127.0.0.1:49621` 的 Node 桥接保留。
- **不写库存的路径必须有明确提示**：器件库、齐套检查、预览都不得产生任何库存变化。
- **版本单一来源**：`package.json`、`extension.json`、`src/iframe/app.js` 的 VERSION 必须一致（当前 3.0.3，本轮升 3.1.0）。
